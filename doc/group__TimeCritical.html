Detailed Description

Functions used by the ISR.

This group contains functions that are executed within the Interrupt Service Routine (ISR) or are closely tied to time-sensitive operations. These functions are optimized for speed and efficiency to ensure the system operates without delays or interruptions.

Note
These functions handle tasks such as ADC sampling, zero-crossing detection, and real-time data processing.

void addToDatalogSum ( )

The rest of the cycle's bookkeeping, the task after the CT2 energy.

  • Adds the power of the cycle that just ended to the datalog sum.
  • Updates the minimum number of ADC sample sets per mains cycle.
  • Counts the cycles of the datalog period, and tells the next positive crossing whether it ends the period.
  • Counts the seconds without diversion, and signals a new mains cycle to the main code.

Confirms the polarity of the current voltage sample for a specific phase.

This routine prevents a zero-crossing point from being declared until a certain number of consecutive samples in the 'other' half of the waveform have been encountered.

Parameters
phaseThe phase number [0..NO_OF_PHASES[.

  • If the polarity differs, the persistence counter is incremented.
  • Once the persistence counter exceeds a predefined threshold, the polarity is confirmed.

Optimized 24×16→40 unsigned multiplication, returning bits 8..39.

Computes (a × b) >> 8 without a 64-bit multiply (which would call __muldi3). Used by the integer energy bucket, where the product of an average power (up to 2^18) and a 16-bit calibration constant needs ~35 bits.

Parameters
resultReference to uint32_t variable to store (a × b) >> 8
aUnsigned value, only its low 24 bits are used (must be < 2^24)
b16-bit unsigned value
Note
On AVR: 6 hardware multiplies, ~30 cycles
The low byte of the product is dropped, not rounded
Fallback available for non-AVR platforms

◆ processDivertedCurrentRawSample()

void processDivertedCurrentRawSample ( const uint16_t rawSample)
inline

Processes the raw sample of CT2, the current diverted to the loads.

CT2 is sampled in every round of the chain, so that the timing never depends on the settings. As processCurrentRawSample(), without the CT filter: the same DC removal (the voltage bias), V x I at x1 scale (V_ADC x I_ADC) into the cycle's sum, which processDivertedEnergy() turns into energy at the positive zero crossing. Without DIVERTED_CT_PRESENT, the sample is dropped.

The voltage sample is the latest one, two conversions (~208 us) before this CT2 sample, against one (~104 us) for CT1.

Parameters
rawSampleThe raw sample of CT2 (left-aligned ADC).

◆ processDivertedEnergy()

void processDivertedEnergy ( )

Turns the cycle's CT2 sum into energy, the task after the contribution.

  • The sum goes through the CT2 table, as the grid's in processLatestContribution(): the cycle's average power in W x 2^Energy::FRACTION_BITS. A cycle of an unexpected length (start-up, missing mains) counts as no energy: no division in the ISR.
  • The sum was taken, not cleared, at the crossing: it is taken off here.
  • The local outputs are read on their port registers. The port holds the states decided for the cycle that starts now, so the states may lag one cycle behind the energy.
  • countDivertedEnergy() counts it on the next CT2 call.

◆ processMinusHalfCycle()

void processMinusHalfCycle ( const uint8_t phase)
inline

Processes the start of a new negative half cycle for the specified phase.

This function is called just after the zero-crossing point of a negative half cycle. It refreshes the DC offset used to remove the DC component from the voltage signal.

Parameters
phaseThe phase number [0..NO_OF_PHASES[.
  • l_filterDC_V is a Q17.15 integrator: processVoltage() adds every i_sampleVminusDC to it, so each sample feeds back with a gain of 1/32768.
  • Here the integrator is simply rescaled to the x64 (left-aligned ADC) domain to give the offset applied to the following cycle.
  • The integrator is free-running: it is never reset, and is not clamped. Its time constant is long enough that a plausible offset drift is tracked smoothly, while a stuck or disconnected VT settles to that input instead of to a fixed limit. See test/native/test_dc_offset_filter for the tracking and step-response cases.
  • On phase 0, beyond the start-up period, the sum of the first half is taken for the prediction (fast_control.h), which the next CT2 call computes (predictEndOfCycle()), for the decision a few sample sets later.

Decides the loads of the next mains cycle, on the prediction.

This task runs once per mains cycle, on the CT2 call of the sample set DECISION_SAMPLE of the negative half cycle (fast_control.h). The physical states and the ports follow on the next two CT2 calls (updatePhysicalLoadStates(), applyDecision()); the zero-crossing triac drivers latch the new states at the next positive zero crossing.

◆ updatePhysicalLoadStates()

void updatePhysicalLoadStates ( )

Updates the physical load states based on logical load priorities and states.

This function maps the logical load states to the physical load states. It ensures that the physical loads are updated according to the logical priorities and states. The function also handles priority rotation if enabled.

The array, logicalLoadState[], contains the on/off state of all logical loads, with element 0 being for the one with the highest priority. The array, physicalLoadState[], contains the on/off state of all physical loads.

The lowest 7 bits of element is the load number as defined in 'physicalLoadState'. The highest bit of each 'loadPrioritiesAndState' determines if the load is ON or OFF. The order of each element in 'loadPrioritiesAndState' determines the load priority. 'loadPrioritiesAndState[i] & loadStateMask' will extract the load number at position 'i' 'loadPrioritiesAndState[i] & loadStateOnBit' will extract the load state at position 'i'

Any other mapping relationships could be configured here.

Note
This function is called during each cycle to ensure the physical load states are synchronized with the logical load states.

◆ updatePortsStates()

void updatePortsStates ( )
inline

Updates the control ports for each of the physical loads.

This function determines the ON/OFF state of each physical load and updates the corresponding control ports.

  • If a load is OFF, its corresponding pin is added to the pinsOFF mask.
  • If a load is ON, its corresponding pin is added to the pinsON mask.
  • Finally, the pins are updated with setPinsState, one write per port, and only on the ports the load pins are on.
  • Overrides are already part of the physical load states, and the relays are driven by the relay engine only: no other pin is ever written here.
